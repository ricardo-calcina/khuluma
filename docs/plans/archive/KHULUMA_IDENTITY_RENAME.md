## 4. Compatibility and exact residual-name policy

Compatibility is an adapter to **one** canonical implementation/root, never two installations writing separate ledgers.

- New `khuluma` checks old default data before initializing an empty profile. Merely sourcing migration helpers, `help`, `--help`, version/identity probes and `config defaults` must be side-effect free: no manifest, directories, import, writer lock, quiescence or warmup. Mutating startup can request the explicit migration tool; it cannot apply a live migration implicitly. Fresh install creates only canonical defaults; migration-aware startup refuses to silently select an unrelated second root.
- Rename public `DICTATE_*` overrides to `KHULUMA_*`, with canonical nonempty value > legacy nonempty value > config/default, preserving existing empty/boolean/zero parsing. Normalize CLI aliases once after current zshenv loading. Bootstrap, installer, Finder adapter and build/signing/updater tools each normalize their own supported canonical/legacy inputs **before first use**; they cannot depend on a later CLI normalizer. Preserve canonical no-warmup, custom-directory and source-provenance settings through child-process environments. Special mappings: `DICTATE_TMUX_WHISPERD_BIN` → `KHULUMA_DAEMON_BIN`; `_ROOT` → `KHULUMA_DAEMON_SOURCE_ROOT`; `_BUILD_ROOT` → `KHULUMA_DAEMON_BUILD_ROOT`. `KHULUMA_CLI` stays. Internal state symbols are renamed directly, without compatibility APIs. Loader aliases are special: old `*_LIB_PATH` / `*_INTERNAL_LIB_DIR` values may point to readable but incompatible old functions/modules. Validate a canonical library API/package marker; recognize/rebind only verified old factory paths, otherwise fail with a migration remedy. Never source old and new helper sets together. If a sourced-library compatibility file proves necessary, it must source/wrap the canonical library, never `exec` it; no such shim is required by the currently identified callers.
- Ship one temporary `tmux-whisper` shim in the first renamed release. It forwards all arguments/stdin/stdout/stderr/exit status to canonical `khuluma`, **except** the explicitly documented old doctor-JSON adapter; it cannot source old libraries or spawn an old daemon. No deprecation chatter on JSON stdout. All known local consumers must move to canonical names in the first rollout.
- Support legacy command/env aliases for the first renamed release (`0.10.x` if available). Review removal at the next minor release after **30 days and explicit known-consumer checks**. Time alone is not evidence that scripts migrated. Keep the compatibility item open with an owner/date until removed; do not claim alias retirement at the initial release.
- The historical formula rename mapping remains for upgrade continuity; old GitHub redirects remain. Legacy data/preferences readers and their test fixtures remain as upgrade support. This does not mean active new writes use the old name.
- `khuluma doctor --json` gets explicit `schema_version: 2` and neutral `install_sanity.{cli_binary,daemon_source,daemon_binary,daemon_socket}` replacing the four old keys (`diagnostics.sh:273–323`). This diagnostic schema change is deliberate; app contract 3 is unaffected because the bridge does not consume doctor. The old-name shim recognizes exactly `doctor --json` (and equivalent parsed flag order) and emits the former key layout without the v2 marker; all other commands are transparent. Update `CONTRIBUTING.md:8` and `docs/CLI_CONTRACTS.md` to name this diagnostic-only schema-version exception while retaining the additive app-contract policy. Test that adapter rather than retaining old keys in canonical output.

**Allowed residuals**, each recorded with a file/symbol/reason in the final report: old-name reads in `LegacyNames`/migration tables; legacy marker/process recognition; compatibility alias tables/shim; old-format fixtures; unchanged dated LOG Done/changelogs/archived plans/name research and this dated plan/frozen rename-evidence snapshot; truthful installation provenance and backups; technical Whisper/FluidAudio/Parakeet/CoreML/API terms; arbitrary vocabulary/cleanup samples; old GitHub redirects/formula rename metadata; old certificate retained for other apps and rollback. No blanket exception for all tests or all docs.

The active VPS product page is current marketing, not historical evidence. The personal site's dated old-project story is historical; preserve it. The user's personal-site saved-project shortcut is explicitly outside this task.
